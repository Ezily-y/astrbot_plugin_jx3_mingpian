# 剑网3 图片创作

发送或引用角色图片，通过 `/生图` 生成名片卡、特写海报或人物图鉴。插件专注图片创作，不查询游戏数据，不再需要 JX3API 令牌或单独绑定区服。

## 使用方法

**支持 `/生图 ...` 和 `@机器人 生图 ...` 两种写法（@机器人 时斜杠可省略）；群里直接发送 `生图 帮助` 也能查看帮助。** 每次使用一张参考图，可把图片与命令放在同一条消息中，也可引用含图片的消息后发送命令。同条消息的附图优先于引用图片。

| 命令 | 参数与用途 |
|---|---|
| `/生图 名片 [角色名] [门派] [区服]` | 三项均选填，未填时留空。生成底卡和头像，叠加已填写的文字及对应门派元素 |
| `/生图 特写 提示词名称或编号` | 提示词必选，按当前列表中的名称或编号切换效果，直接输出图片 |
| `/生图 图鉴 [角色名]` | 角色名选填，未填时留空。先生成立绘，再由图片理解模型编写设定并渲染图鉴 |
| `/生图 帮助` | 无需图片，展示完整用法与当前可用提示词 |

方括号表示参数可省略，实际发送时不要带方括号。名片参数按角色名、门派、区服的顺序填写，可省略后面的字段；需要跳过前面或中间的字段时用 `-` 占位。区服只作为卡面文字展示，不会查询或校验游戏角色。单个角色信息参数不支持空格。特写提示词名称可以包含空格，按完整名称匹配。

### 示例

将以下命令与一张角色图片同时发送，或先引用角色图片再发送：

```text
/生图 名片
/生图 名片 小螺卜头 七秀
/生图 名片 小螺卜头 七秀 梦江南
/生图 名片 - 七秀
/生图 名片 - - 梦江南
/生图 特写 双眼特写
/生图 特写 4
/生图 图鉴 小螺卜头
/生图 图鉴
```

查看提示词与用法：

```text
/生图 帮助
```

- 图片支持 PNG、JPEG、WebP、GIF，文件大小不超过 20 MB；一次只使用一张参考图。
- 引用消息须由平台适配器提供图片内容；无法读取引用图片时，请把图片与命令一起重发。
- 缺图、缺特写提示词、参数过多或提示词无效时，仅返回提示，不开始生图。省略角色名、门派、区服不影响生成。
- 不创建序号等待会话，不存在超时自动生成；切换效果需重新发送完整的 `/生图 特写 ...` 命令并附图或引用图片。
- 名片展示信息由用户选填，未填不显示占位文字；未填门派时不叠加门派徽记或门派诗。填写门派时，支持范围以错误提示列出的名单为准。
- 图鉴中的角色名由用户选填，未填时留空且不自动起名；其余设定文案由模型创作，成品底部有对应说明。

## 内置提示词与切换

默认提供五种特写效果：

| 默认编号 | 名称 | 默认比例 |
|---|---|---|
| 1 | 双眼特写 | 21:9 |
| 2 | 双眼特写（电影黑条） | 21:9 |
| 3 | 多视角海报 | 21:9 |
| 4 | 手办化 | 不指定 |
| 5 | 破屏而出 | 不指定 |

通过名称或编号选择，例如 `/生图 特写 手办化` 与默认配置下的 `/生图 特写 4` 等效。

管理员可在配置的「特写内置与自定义提示词」中增删、重排、重命名或修改内容。每条包含名称、比例和提示词内容；**空内容条目不会进入可选列表，`/生图 帮助` 会在「内容为空、未启用」中列出名称，补全并保存后即可选择**；名称留空时自动使用「提示词N」。**编号以 `/生图 帮助` 当前展示的清单为准**，配置重排会改变编号；长期使用建议按名称选择。名称重复时请按编号选择。

该列表用于特写效果。名片使用内置的卡面与头像提示词；图鉴立绘提示词通过单独的配置项修改。切换特写不会更改名片或图鉴的提示词。

## 配置

生图接口的多个方案统一在 AstrBot 插件详情页的「生图设置」页面里管理；生图后端和 Codex 开关在插件卡片的「配置」弹窗里设置。配置弹窗里的接口地址、密钥、模型和方案列表已隐藏，避免和页面出现两份数据。

1. 在插件配置弹窗里选择「生图后端」：OpenAI 兼容接口或本机 Codex CLI。选择 Codex 时勾选「启用本机 Codex 生图」，并填写可执行文件、模型和超时。
2. 打开「生图设置」页面，点击「添加方案」：填写方案名称、接口地址、密钥；点击「刷新模型」拉取服务端模型并选择，列表中没有时选「手动填写模型 ID」。
3. 多个方案可以上移/下移排序；「当前使用」是主方案，失败后按列表顺序尝试下一个方案（受「自动降级」开关控制）。
4. 每个方案都可以测试：连通性检查地址、鉴权、模型是否在列表中；实际生图测试会生成一张 1024×1024 图片，消耗额度。
5. 点击「保存设置」后立即生效，无需重新加载插件。

已保存的密钥不会回填页面，只显示已配置条数；密钥输入框留空保留原密钥，填写新内容会替换该方案的密钥列表（每行一条）。刷新模型、连通性测试和生图测试使用页面当前草稿，不修改正在使用的配置。

首次安装或升级后需重新加载插件以注册设置页面。旧版单字段的地址/密钥/模型会在第一次打开页面时迁移成第一条方案，保存后写回 `image_api_profiles`。

| 配置项 | 说明 |
|---|---|
| 生图后端 | 插件配置弹窗里选择；OpenAI 兼容接口或本机 Codex CLI |
| 启用本机 Codex 生图、Codex 可执行文件 / 模型名 / 超时 | 插件配置弹窗里设置；Codex CLI 路径、可选模型和 30～3600 秒超时 |
| 接口方案（名称、地址、密钥、模型） | 在「生图设置」页按方案管理；地址省略 `/v1` 时自动补全，密钥支持多条轮询 |
| 顺序 / 当前使用 | 在「生图设置」页上移/下移；当前使用为主方案，失败按顺序降级 |
| 自动降级 | 「生图设置」页开关；关闭后当前方案失败不会尝试下一个 |
| 同时生成上限 | 默认 3，范围 1～20，覆盖图片读取、生成、渲染和发送过程；达到上限时提示稍后再试 |
| 开始生图任务提示 | 参考图和参数校验通过后发送的等待文案 |
| 名片卡比例 | 默认 16:9；头像固定 1:1 |
| 特写内置与自定义提示词 | 各条提示词包含独立的名称、比例和内容；不指定比例时交给接口决定尺寸；内容为空的条目会在帮助里标记为未启用 |
| 人物图鉴立绘提示词 | 留空时使用内置值，立绘比例固定 4:3 |
| 启用白名单、白名单 | 沿用用户 ID 或统一消息来源控制，对帮助和生成均生效 |

名片会并发生成底卡和头像，发起两次生图请求；特写发起一次生图请求；图鉴发起一次生图请求和一次 AstrBot 对话模型请求。图鉴需要当前会话配置支持图片理解的对话模型。生图请求不主动使用 HTTP 代理。

## 与游戏数据查询工具配合

可先使用 `astrbot_plugin_jx3` 的「名片」「全名片」等命令取得角色图片，再引用所需图片发送 `/生图 ...`。两个插件互不依赖，不读取彼此的配置、绑定数据库或缓存。用户也可以直接上传自己的角色截图。

## 从 1.x 升级

- 原「名片卡」「名片特写」「名片图鉴」「名片绑定」「查看名片区服」「名片帮助」入口已移除，统一使用 `/生图`。
- 不再读取 JX3API 地址、令牌、代理及 TLS 配置，也不再请求角色详情和历史名片。
- 旧版 `bindings.json` 不再使用，升级过程不会删除原绑定文件。
- 生图地址、密钥、模型、并发上限、提示词、比例与白名单的配置键保持兼容。
- 安装新增依赖并重新加载插件后，通过 `/生图 帮助` 查看当前用法。

- 新增 OpenAI 兼容接口与本机 Codex CLI 两种生图后端，以及 DashScope qwen-image 适配。
- 依赖精简为 `aiohttp`、`Pillow` 与 Windows 下的 `tzdata`。

## 开发

```text
python -m pytest -q
python tools/smoke_render.py
```

运行测试需要 `pytest`、`pytest-asyncio`；离线渲染检查还需要 `jinja2`、`playwright` 及其 Chromium 浏览器。插件运行依赖见 `requirements.txt`。

核心文件：`main.py` 为唯一命令入口；`core/input_image.py` 读取和校验用户图片；`core/prompts.py` 维护提示词选择与清单；`core/card.py` 生成卡面与特写；`core/tujian.py` 处理图鉴设定；`templates/standalone/` 保存名片及图鉴模板。

门派诗文本为公开资料整理，其中部分缺失内容由模型补写，来源说明见 `core/mingpian_data.py`。
